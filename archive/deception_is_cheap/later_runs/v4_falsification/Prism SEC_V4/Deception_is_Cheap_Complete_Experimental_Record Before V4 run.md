# Deception is Cheap — Complete Experimental Record
**Author:** Alon Babchuk  
**Date range:** 2025–May 2026  
**Purpose:** Full research record for white paper / final report.  
Documents every experimental run, exact hardware settings, what each version  
of the code did, what the results showed, and why each result looked the way it did.

---

## THE CORE QUESTION

Do large language models consume measurably different amounts of GPU energy  
when processing deceptive financial text versus honest financial text?  
And if so, does that difference reflect something real about how the model  
is processing the content — or is it an artifact of other variables?

## PHASE 1 — THE ORIGINAL FINDING

### Hardware
- **GPU:** NVIDIA B300 (original run) / NVIDIA B200 (replication run)
- **Platform:** RunPod cloud
- **Model precision:** float16
- **Generation:** model.generate(), max_new_tokens=50, greedy decoding
- **KV cache:** ON by default (model.generate() handles this automatically)
- **Power measurement:** pynvml polling every 10ms via background thread

### Corpus
6 texts total — 2 types × 3 domains:
- Type 1: Fraudulent (SEC complaints): MG Capital, Start Options, Guess & Co.
- Type 2: Compliant (EDGAR 10-K filings): AB Commercial, Workday, Tech & Energy Transition

### Result
- 11/12 measurements: Fraud < Compliant power draw
- Replicated on B200 hardware: 12/12
- Power gap: up to ~113W (33%) in some cases (Llama-3.1-8B, Technology domain)
- Pattern: consistent direction across all 4 model architectures

### Why it looked so clean
The corpus had a **perfect confound**. All fraudulent texts were shorter and  
linguistically simpler than all compliant texts. The compliant texts were dense  
legal boilerplate; the fraud texts were promotional pitches. The models found  
the legal language harder to continue because it involves more conditional  
clauses, hedges, and syntactic complexity. This was not yet understood.

### What this run correctly measured
The GPU genuinely works harder when continuing complex, hedged, multi-clause  
legal language than when continuing simple, assertive promotional language.  
The attribution to "deception" was premature — but the underlying computational  
signal was real.

## PHASE 2 (v2) — CONFOUND CONTROLS

### Script: `gemini-code-1778974323998.py`
**Generated by Gemini. Executed on RunPod.**

### Hardware
- **GPU:** NVIDIA A100 SXM 80GB
- **Platform:** RunPod cloud, 200GB container disk
- **Model precision:** float16
- **Generation:** model.generate(), max_new_tokens=100
- **KV cache:** ON by default (model.generate())
- **Warmup:** 5-token warmup per text (`model.generate(**inputs, max_new_tokens=5)`)
- **Power measurement:** pynvml thread polling every 10ms
- **Attention:** Default (flash attention / SDPA — not eager)

### Corpus
12 texts — 4 types × 3 domains. New additions vs Phase 1:
- Type 3 (Hedged Honest): Federal Reserve Beige Book excerpts
- Type 4 (Certain Honest): CBO Projection excerpts
These were added specifically to isolate linguistic complexity from deception.

### Result
- Power range: 165–210W
- Differences between text types: ~5–6% (5–10W)
- Domain 2 (Technology) anomaly: Fraud text drew MORE power than Compliant  
  (reversing Phase 1 pattern for that domain)
- No consistent direction across all 4 models and 3 domains

### Why differences collapsed
The switch from B300/B200 hardware to A100 was not the primary cause.  
The primary cause was the **generation method**. `model.generate()` uses  
the KV cache automatically and optimally — each step only processes the  
single newest token. This means the GPU does nearly the same amount of work  
for each token regardless of what the input text said. The signal from text  
complexity was almost entirely bypassed.

Additionally, the 5-token warmup (~250ms) was insufficient to stabilise the  
A100's thermal state (thermal time constant: 15–30 seconds). However, since  
all 12 texts were measured sequentially per model, by texts 3–4 the GPU was  
thermally stable. The warmup issue affected absolute power levels but not  
relative differences within the same model run.

### What this run correctly identified
Linguistic complexity and rhetorical certainty are real variables. The  
"Deception is Cheap" signal cannot be attributed to deception per se — it  
is carried by the specific linguistic properties that fraudulent text happens  
to share with other simple, certain language.

## v3-A — FIRST V3 RUN

### Script: `run_sec_detection_v3.py`
**Written by Claude, executed by user on RunPod.**

### Key settings (extracted from script)
```python
USE_CACHE        = False
ATTN_IMPL        = "eager"
GENERATION_STEPS = 50
WARMUP_TOKENS    = 50
past_key_values  = NOT USED (not in script)
float() cast     = NOT USED (logits passed as float16)
warmup location  = Once per model (not per text)
```

### Hardware
- **GPU:** NVIDIA A100 SXM 80GB
- **Platform:** RunPod
- **Model precision:** float16
- **Attention:** eager (explicit O(n²) attention matrix)
- **KV cache:** DISABLED via use_cache=False
- **Generation loop:** Custom step-by-step, passes full `current_ids` at every step

### The word count mechanism (critical)
With `use_cache=False` and a growing `current_ids` tensor, at every step  
the model computes full attention over ALL previous tokens from scratch:
- Step 1: attention over (input_length + 1) tokens
- Step 2: attention over (input_length + 2) tokens
- Step 50: attention over (input_length + 50) tokens

Attention computation is O(n²). Total compute across 50 steps grows  
with the square of input_length. **GPU power becomes a direct function  
of text word count, not text complexity.**

### Word counts in v3 corpus
| Domain | Text type | Word count |
|--------|-----------|-----------|
| Domain 1 Real Estate | Fraudulent | ~94 words |
| Domain 1 Real Estate | Compliant | ~73 words |
| Domain 1 Real Estate | Hedged Honest | ~62 words |
| Domain 1 Real Estate | Certain Honest | ~61 words |
| Domain 2 Technology | Fraudulent | ~70 words |
| Domain 2 Technology | Compliant | ~84 words |
| Domain 2 Technology | Hedged Honest | ~65 words |
| Domain 2 Technology | Certain Honest | ~58 words |

### Result
- Power range: 258–320W
- Fraud HIGHEST in Domains 1 and 3 (fraud text is longer)
- Fraud LOWER in Domain 2 (fraud text is shorter than compliant)
- Pattern perfectly tracks word count, not text type

### What Gemini said (correct)
"You built the world's most expensive word counter." The GPU with  
use_cache=False and a growing sequence measures text length, not  
cognitive complexity.

## v3-B — USE_CACHE=TRUE (BROKEN LOOP)

### Script: `run_sec_detection_v3_User_true.py`
**User changed ONE setting from v3-A: `USE_CACHE = False` → `USE_CACHE = True`**

### Key settings
```python
USE_CACHE        = True        ← ONLY CHANGE from v3-A
ATTN_IMPL        = "eager"
GENERATION_STEPS = 50
past_key_values  = NOT USED    ← still not in script
float() cast     = NOT USED
warmup location  = Once per model
```

### Why the cache was not actually used
Setting `use_cache=True` in the `model()` forward call tells the model  
to **compute and return** the key-value pairs. But unless those pairs  
are stored and fed back in on the next call, the model cannot use them.

The loop still passed `current_ids` (the full growing sequence) at every step  
and did not receive or pass `past_key_values`. The GPU was therefore still  
computing full attention over the entire sequence on every step —  
functionally identical to `use_cache=False`.

### Result (shown in uploaded docx)
```
Power range: 210–295W
Llama-3.1-8B  Domain_1: Fraud=269.6  Compl=260.5  Hedged=251.9  Certain=253.0
Mistral-7B    Domain_1: Fraud=264.5  Compl=234.4  Hedged=233.8  Certain=220.3
Qwen-2.5-7B   Domain_1: Fraud=259.1  Compl=247.9  Hedged=247.3  Certain=246.2
Gemma-2-9B    Domain_1: Fraud=249.6  Compl=222.2  Hedged=210.4  Certain=210.2
```

- Fraud HIGHEST across Domain 1 (because it has the most words)
- Technology domain: Compliant highest (Compliant is the longest text in Domain 2)
- Pattern: identical to v3-A — still word count artifact
- Power slightly lower than v3-A (164W vs 200W base) because  
  use_cache=True reduces some internal bookkeeping overhead even  
  without proper past_key_values handling

### Note on filename ("FED_changed")
The FED (Federal Reserve Beige Book) texts in this script are **identical**  
to the original v3-A script. The "FED_changed" label appears to refer to  
the implementation change (adding proper past_key_values handling in  
the measure_text function), not to a text change. The corpus texts  
did not change between any v3 scripts.

## v3-C — PROPER KV CACHE (RESULTS UPLOADED)

### Script: `run_sec_detection_v3_User_true_and_FED_changed.py`
**Gemini added the correct past_key_values loop. User executed on RunPod.**

### Key settings
```python
USE_CACHE        = True
ATTN_IMPL        = "eager"
GENERATION_STEPS = 50
WARMUP_TOKENS    = 50
past_key_values  = CORRECTLY PASSED FORWARD  ← key fix
float() cast     = NOT USED                  ← entropy bug remains
warmup location  = Once per model            ← cold-start remains
```

### The correct KV cache implementation
```python
past_key_values = None
for step in range(GENERATION_STEPS):
    if USE_CACHE and past_key_values is not None:
        model_inputs = current_ids[:, -1:]    # Only the newest token
    else:
        model_inputs = current_ids             # Full sequence on step 0 only
    outputs = model(model_inputs,
                    use_cache=True,
                    past_key_values=past_key_values)
    past_key_values = outputs.past_key_values  # Carry forward
```

With this fix, after step 0, the GPU processes only ONE new token per step.  
Attention computation drops from O(n²) per step to O(1) per step.  
Word count is no longer a confound.

### Hardware and result
- **GPU:** NVIDIA A100 SXM 80GB
- **Power range:** 141–178W (dramatically lower — cache working correctly)
- **Results uploaded:** deception_is_cheap_v3_results.json, v3_trajectories.csv
- **48 records:** 4 models × 3 domains × 4 text types

### Domain 1 result (full mean):
```
               Fraud    Compl   Hedged  Certain
Llama-3.1-8B:  152.9    169.5   171.0   170.3  ← Fraud cheapest
Mistral-7B:    147.1    160.6   162.9   159.4  ← Fraud cheapest
Qwen-2.5-7B:   162.3    174.3   174.1   175.4  ← Fraud cheapest
Gemma-2-9B:    141.5    150.2   150.6   151.7  ← Fraud cheapest
```

This appears to replicate the Phase 1 finding: Fraud < all honest variants.  
**But it is a cold-start artifact.** See next section.

### The cold-start thermal artifact (discovered in post-analysis)

Evidence from the trajectory CSV (step 0 power for each text):
```
Model: Llama-3.1-8B
  Domain 1 Fraudulent step 0: 69.6W   ← GPU COLD (measured first)
  Domain 1 Compliant  step 0: 166.7W  ← GPU warm (measured second)
  Domain 1 Hedged     step 0: 164.3W  ← GPU warm (measured third)
  Domain 2 Fraudulent step 0: 161.7W  ← GPU stable (Domain 1 already completed)
```

Type_1_Fraudulent in Domain_1 is always the FIRST text measured after model load.  
The 50-token warmup with KV cache properly enabled takes approximately 1–2 seconds  
(much faster than the cache-off runs because only 1 token is processed per step).  
The A100 thermal time constant is 15–30 seconds. The GPU was still ramping up  
when the Fraudulent text was measured, pulling only 69.6W at step 0 instead  
of the stable 160–170W seen in subsequent texts.

### Stable-step analysis (steps 40–49 only, GPU fully warm):
```
Llama-3.1-8B, Domain 1 (steps 40–49 only):
  Fraudulent:   170.7W
  Compliant:    167.5W
  Hedged:       164.0W
  Certain:      164.1W
```

When cold-start steps are excluded, **Fraud is no longer cheapest** —  
the pattern reverses. Hedged and Certain are the cheapest at stable state.  
The "Fraud cheapest" result from the full mean is entirely explained by  
the 69W cold readings in steps 0–10.

### Token signals — entropy NaN bug
All 2400 entropy readings in the trajectory CSV are NaN.

Root cause: `compute_entropy()` passes float16 logits to `torch.softmax()`.  
In float16, very small probabilities underflow to exactly 0.  
`torch.log(0) = -inf`. The sum `-(probs * log_probs)` becomes NaN.

**Fix:** One line change in all signal functions:
```python
# Before (buggy):
probs = torch.softmax(logits, dim=-1)
# After (correct):
probs = torch.softmax(logits.float(), dim=-1)
```

### Token signals — branching factor (partial capture)
Branching factor does not NaN because it uses top-k probabilities.  
But the values are unreliable due to the cold-start effect at step 0.

Llama, Domain 1, mean branching:
- Fraudulent: 6.917 (highest) — driven by step 0 branching=22.19 on cold GPU
- Compliant: 5.830
- Hedged: 4.720
- Certain: 4.036 (lowest)

This ordering is COUNTERINTUITIVE — Fraud shows highest branching, not lowest.  
This is also a cold-start artifact: step 0 captures the model's initial  
exploration of a cold prompt, not a stable processing state.

### Top-k concentration (most reliable signal in v3-C)
Top-k concentration (fraction of probability mass in top 10 tokens) does  
not suffer from the NaN bug and is relatively stable across steps:

Llama, Domain 1:
- Fraudulent: 0.8996 (LOWEST concentration — most diffuse)
- Compliant: 0.9274
- Hedged: 0.9470
- Certain: 0.9557 (HIGHEST concentration — most narrow)

**This ordering is unexpected.** Fraudulent text should, by hypothesis,  
produce HIGH concentration (the model locks onto narrow continuations).  
Instead, Fraudulent shows the LOWEST concentration. This may reflect  
that the fraud text's promotional vocabulary triggers diverse associations  
in the model, while certain/projected language ("will decline by 8.5%")  
locks the model more deterministically.

## CROSS-EXPERIMENT CONFOUND CATALOGUE

### Confound 1: Corpus linguistic confound (Phase 1)
**What:** Fraudulent texts were shorter and simpler than compliant texts.  
**Effect:** Any measure sensitive to text length or vocabulary complexity  
would show fraud as "cheaper."  
**Resolution:** Added Types 3 and 4 in v2 corpus. Partially resolves.

### Confound 2: Generation method sensitivity difference (Phase 1 vs v2)
**What:** Phase 1 used B300/B200 with a different default attention implementation.  
v2 used A100 with model.generate() and KV cache fully enabled.  
**Effect:** Phase 1 signal (~33%) collapsed to ~5% in v2 even with same corpus.  
**Resolution:** Need a step-by-step loop that controls cache behaviour explicitly.  
This led to the v3 series.

### Confound 3: Word count artifact (v3-A and v3-B)
**What:** use_cache=False with growing sequence makes power = f(word_length).  
**Effect:** Longer texts always draw more power regardless of content.  
**Resolution:** Proper KV cache with past_key_values correctly passed.  
Implemented in v3-C.

### Confound 4: Broken KV cache loop (v3-B)
**What:** Setting use_cache=True without passing past_key_values forward  
doesn't actually activate the cache.  
**Effect:** Identical to use_cache=False from the GPU's perspective.  
**Resolution:** The specific loop structure in v3-C with explicit past_key_values.

### Confound 5: Cold-start thermal artifact (v3-C)
**What:** The 50-token per-model warmup with proper KV cache takes ~1 second.  
GPU thermal stabilisation requires 15–30 seconds. Type_1_Fraudulent in Domain_1  
is always measured first, always on the coldest GPU.  
**Effect:** Fraud Domain 1 draws ~70W at step 0 vs ~165W for all subsequent texts.  
Full-mean power for Fraud is artificially low.  
**Resolution (for v4):**  
  (a) Per-text warmup of 200 tokens before each of the 12 measurements.  
  (b) Randomise text processing order between runs.  
  (c) Analyse only stable steps (20–50) for primary power metric.

### Confound 6: Entropy NaN bug (all v3 runs)
**What:** float16 logits passed to softmax cause underflow to 0, making log(0) = NaN.  
**Effect:** All entropy and KL divergence readings are lost.  
**Resolution (for v4):** `logits.float()` before all signal computations.

## WHAT v4 MUST FIX

### Fix 1 — Per-text warmup (CRITICAL)
Run 200 tokens of neutral economic text before each of the 12 measurements.  
Not just once per model — before each text.  
This adds ~2–3 minutes per model but eliminates the cold-start artifact.

### Fix 2 — Randomise processing order
Run the full experiment twice:
- Run A: Type_1 → Type_2 → Type_3 → Type_4 (standard order)
- Run B: Type_4 → Type_3 → Type_2 → Type_1 (reversed order)

If the "Fraud cheapest" finding holds in both orderings, it is real.  
If it only appears in the run where Fraud is measured first, it is thermal.

### Fix 3 — Float32 cast for all signal functions (CRITICAL)
```python
# Every signal function must start with:
probs = torch.softmax(logits.float(), dim=-1)
# NOT:
probs = torch.softmax(logits, dim=-1)  # ← causes NaN in float16
```

### Fix 4 — KV cache with proper past_key_values (already done in v3-C)
The v3-C implementation is correct. Carry forward exactly.

### Fix 5 — Use stable steps only for primary metric
Power reading steps 0–19 include the GPU ramp-up phase even with per-text warmup.  
Primary reported metric: mean power of steps 20–50.  
Full 50-step mean also reported but labelled as secondary.

### Fix 6 — Add DCI proxy (new in v4)
Real-time DCI proxy computed at every step:
```python
DCI_proxy(t) = C_topk / (H_norm × B_norm)
# where H_norm = H / log(vocab_size), B_norm = B / 50
```

## THEORETICAL FRAMING (updated to reflect all experimental findings)

### The original claim (now known to be overstated)
"Deception is computationally cheap."

### The refined claim (supported by evidence)
Rhetorically compressed, epistemically closed language — language characterised  
by high DCI (high Directionality, low Reversibility, low Complexity Tolerance) —  
tends to be computationally cheaper for transformer models to continue than  
language with genuine epistemic openness.

Fraudulent financial text is a naturally occurring example of this compression  
regime. The signal is real but is mediated by linguistic structure, not by  
deceptive intent per se.

### The training pressure argument (unchanged)
If AI systems are optimised for computational efficiency during training,  
efficiency pressure will preferentially reinforce the production of rhetorically  
compressed language — the same linguistic profile that characterises financial  
fraud in this dataset.

This does not require intentional deception. The system simply learns that  
narrow, certain, high-DCI outputs cost less to produce. The result is a model  
that mimics the rhetorical style of fraudsters without any malicious intent.

### The DCI-energy synthesis (new in v4)
DCI (semantic layer) and GPU energy (hardware layer) measure the same underlying  
property — processing openness — from different angles. Where they agree, the  
signal is strong. Where they diverge (e.g., legal boilerplate: low DCI but  
variable energy due to training data frequency), they provide complementary  
diagnostic information.

A system that scores low on DCI AND consumes low energy is the clearest  
flag for engineered compliance (the Felix Harder pattern). A system that  
scores low on DCI AND consumes high energy is more likely to be genuinely  
epistemically open in its processing.
